# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`claude-ide` (plugin name `ide-panes`; names starting with `claude-` are reserved by the validator): an IDE-like interface built *inside* Claude Code as a mod (a plugin of function hooks): panes, bands above the prompt, status line entries, slash commands, tool-call hooks. Not a standalone app: no DOM, no Node, no bundler.

Before writing or debugging hook code, load the `plugin-authoring` skill. It has the current API, the examples and the path to this build's `claude-code.d.ts`.

## Layout

The repo root is the plugin folder:

- `.claude-plugin/plugin.json`: `{ "name": "ide-panes", "version": "...", "description": "...", "author": {...}, "types": "./types/index.d.ts", "userConfig": {...} }`
- `.claude-plugin/marketplace.json`: a one-plugin marketplace (`ide-panes`, source `./`): `claude plugin marketplace add io-magestix/claude-ide-mx`, then `claude plugin install ide-panes@ide-panes`. With it present, `claude plugin validate .` checks only the marketplace; validate `.claude-plugin/plugin.json` for the plugin itself. An install copies a version: bump `version` for `claude plugin update` to pick up changes.
- `hooks/hooks.json`: `{ "modules": ["./register.tsx"] }`
- `hooks/register.tsx`: entry point, `export const register: Register = (on, options) => { ... }`, with `Register` imported from `'claude-code'`. Feature modules export a named `register(on)`, and the entry imports it by name (`import { register as registerExplorer } from './explorer-panel'`). The validator rejects passing `on` through a namespace import (`explorer.register(on)`).
- `types/index.d.ts`: the `$.state` contract. Every value kept in `$.state` must be declared in `interface PluginState` under the plugin name, and `claude plugin validate` enforces this.
- `hooks/**/*.test.ts`: tests run by `claude plugin test`
- `.claude-plugin/types/`: generated by the engine on load (API, tool and MCP typings, `tsconfig.json`). Do not edit it, and keep it out of git.

## Commands

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .          # run Claude Code with this mod; saving a file hot-reloads it
claude plugin validate .claude-plugin/plugin.json               # manifest, hooks and $.state keys checked against the contract
claude plugin validate .                                        # the marketplace manifest only (`.claude-plugin/marketplace.json`)
npx -p typescript tsc -p .                                      # type-check (needs .claude-plugin/types/, laid down after the first load)
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude plugin test .        # run all *.test.ts against the real engine
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --debug --plugin-dir .  # debug log: every hook error and every refused ui.render tree
```

Function hooks are early access: without `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` the mod does not load and `claude plugin test` runs nothing.

Known baseline (Claude Code 2.1.283): the 9 `previewEngines` tests fail, and `tsc` reports the same 9 call sites. The test kit no longer takes a test's `options`, and nothing else in it reaches a plugin's `userConfig` (no `config.set` writer, and an inline test plugin cannot import the real module), so they stay as written until the kit takes options again. Compare a run against that, not against zero. If `tsc` also reports `unknown` tool inputs (`e.file_path`, `e.command`), `.claude-plugin/types/` was written without the built-in tool table (`BuiltinToolInputs` empty): load the mod again or run `/plugin-types .claude-plugin/types`. The tests fake `HOME` as `/Users/u`: on macOS `/home` is an automount, and the engine refuses `$.fs` writes there as a network location.

Under tmux the engine emits 256 colors; `tmux new-session -e COLORTERM=truecolor -e CLAUDE_CODE_TMUX_TRUECOLOR=1 ...` gives truecolor for live checks.

There is no single-test flag; to run one test, narrow the test files or the `test(...)` calls in a file.

## Architecture of a mod

- `on(event, matcher?, hook)` registers a hook. Each hook is `($, e, next)`:
  - `$` is the engine interface (`$.ui`, `$.state`, `$.store`, `$.fs`, `$.process`, `$.clock`, `$.tool`, `$.model`, `$.command`, ...).
  - `e` is the event input, frozen.
  - `next(e)` passes to the plugins beneath and then the engine's default. Returning without calling `next` overrides the default, and `next({ ...e, x })` rewrites what the rest of the chain sees.
- UI is JSX compiled against the global `h`. Get elements from the surface: `const { Box, Text, Button } = $.ui.resolve(e)`. `e.surface` is `terminal | desktop | vscode | mobile`, so don't assume terminal.
- Panes: open one with `$.ui.open({ id, title })` and draw it from `on('ui.render', { component: 'Pane', requestId: id }, ...)`. A pane opened unprompted (`session.start`, a timer) only seats at 144 or more terminal columns; one opened by user action seats at any width.
- Section titles: a bordered Box clips its children, so a border title is an absolute Box (`top={0}`) placed after the bordered Box inside an unbordered wrapper of the same size.
- Band above the prompt: `ui.render` on `{ component: 'AbovePrompt' }`. Status line: `$.ui.status(text)`. Toasts: `$.ui.toast(text)`.
- Commands: `$.command.register(...)` in `session.start`, handled by a `command.run` hook.
- Reactive state: `atom(ref, initial)`, `read($, atom)` while rendering, and `update($, atom, fn)` from handlers. Writes redraw the components that read the atom.
- Reload semantics: each reload re-runs `register` and fires `session.start` again. `$.state` (per session) and `$.store` (across sessions) persist; module-level variables reset. Keep anything that must survive a reload in `$.state` or `$.store`, and make `session.start` idempotent.
- A `ui.render` tree that fails validation is replaced by the engine's default rendering, with a dim transcript line `ide-panes: ui.render (<Component>) refused: <reason>`. Check that line first when UI doesn't appear.
- Write UI tests once and loop them over `['terminal', 'desktop'] as const`.

For any API detail, grep the generated `.claude-plugin/types/claude-code/index.d.ts` (or the skill's `claude-code.d.ts` before the first load) for the event or noun name, e.g. `'tool.call'`, `Pane: {`.

## Glossary

Use these names in code, comments, tests and chat.

- **Panel**: one whole IDE view, Explorer or Git (engine term: pane, `$.ui.open`, `component: 'Pane'`).
- **Section**: a named, bordered area inside a panel, e.g. Git's Branches, Commits, Info, Graph, Files, Diff Preview. Its name sits on its top border as a tinted Text label (key `title:<name>`); pressing it does nothing.
- **Panel tabs**: a panel's header tabs, switching its whole layout (Git: Overview / Graph / Change Log; Explorer: Files / Unity).
- **Header lines**: each panel draws a title row (`header`: in `header:tabs` the panel name, a `|` divider, the panel tabs, a `|` divider, then the actions (Explorer: its action Buttons in `header:actions`, then dim "not a Unity project" when it applies; Git: `Back`, `Fetch`, `Pull`), every element 2 cells apart, cut at the right end on a narrow pane; ⚙ right under the pane's ✕), then, Explorer only, the interactive line (`header:ask`), drawn only while something asks: a one-row alert, the question or name field on the left, its Buttons in the right corner. Row budget: Explorer 1 header row (2 while a bar is up), Git 1. Every Button label is capitalized (`Refresh`, `Copy Path`, `Fetch`, `Cancel`, ...); keys stay lowercase.
- **Settings sheet**: the ⚙ overlay drawn last over a panel from body row 1 down (dimmed backdrop, drop shadow, card); its Buttons are keyed `settings:*`.
- **Diff view**: Git's full-panel Files | Diff Preview of one commit, opened from a commit row's `⧉` Button.
- **Edit section**: the Explorer's in-pane editor, standing in for Preview while a file is open for editing (`edit` or `new`); drawn by a `Client` (`editor-client.tsx`).
- **Splitter**: the draggable seam between two adjacent sections, a `Client` two cells across covering both frames' borders (grab either side), drawn last in the container holding both sections (terminal and desktop only).
- **Horizontal bar**: a one-row scrollbar (`━` thumb, `─` track) overlaid on a text section's bottom border while a line is wider than the room; dragged (a `Client`, `scrollbar-client.tsx` `axis: 'x'`; static Text without one) it scrolls the text sideways. A line scrolled past its end draws as `' '`, keeping its row. Lines are cut by column with `hooks/shared/hscroll.ts` (`widest`, `sliceCols`, `sliceDiffCols`: tabs expanded the way `Code` draws them, CJK/emoji 2 columns). Only Preview, Edit, Info and Diff Preview have one; list sections keep their fitted rows.
- **Row client**: on terminal and desktop, each Files tree row is a `Client` (`hooks/explorer-panel/row-client.tsx`, key `item:<path>`) drawing mark, rails, arrow and name, followed by a blank 1-cell `row:<path>` Button that carries the keyboard ring. It posts `{ hit, ctrl?, shift? }` (`mark`, `arrow`, `name` by `rowHit` in `tree.ts`, or `double`) to the `ui.message` hook.
- **Branch row client**: on terminal and desktop, each Git Branches row is a `Client` (`hooks/git-panel/branch-client.tsx`, key `bitem:<k>`, `k` a folder or category key or `b:<branch>`) drawing bar, rails, arrow or `*` slot and label, followed by a blank 1-cell `branch:<name>` / `bdir:<key>` Button that carries the keyboard ring. It posts `{ hit }` (`arrow`, `name` by `branchHit` in `git.ts`, or `double`; the click gesture shared with the row client, `hooks/shared/row-gesture.ts`) to the `ui.message` hook.
- **Link client**: on terminal and desktop, each pressable link run of rendered markdown in Preview is a `Client` (`hooks/explorer-panel/link-client.tsx`, key `md:link:<i>`) laid exactly over its Text and drawing the same underlined accent label. A left down and up inside it posts `{ link: i, path, offset }` (`i` indexes `mdShown.links`; a press whose `path` or `offset` is not `mdShown`'s is ignored) to the `ui.message` hook; the wheel stays the pane's.
- **Preview engine**: what draws a file in Preview: `code`, `markdown`, `image`, `svg` or a custom command (`engineOf`, `preview.ts`).
- **Marks**: the Explorer's multi-selection (`explorer.marked`), empty or 2+ paths; one left over becomes the selection.
- **Split pane**: the one pane, `ide-split`: the Explorer on top, Git below, a seam between them. The ids `ide-explorer` and `ide-git` still draw a panel alone (the tests mount them), but nothing opens them.
- Not "block": in `git.ts`, `block` means a diff file's header block.

## Features

- `/ide-panels` is the only command: it opens the split pane (`openPanels`; an open one is only raised) and saves the window's columns (`$.store` `window:columns`, `WINDOW_KEY`). Closing the pane (the ✕, ctrl+x x, another plugin; not the engine's unload) asks first while the editor has unsaved text (the explorer's one `ui.close` hook).
- Session opening (Settings `autoOpen`, on by default; `openOnStart`, `closeOnExit` in the explorer): `session.start` of a new interactive session (its `explorer` state still at version 0, so not a reload; not a `-p` run) opens the split pane after `next(e)` when no pane is open, without `focus` (the prompt keeps the keyboard), the split pane asking 20% of `window:columns` (none saved: the dock's own share). Opened unasked, it waits undrawn below the engine's floor (144 columns, 110 for an id the person opened before) until the terminal widens or `/ide-panels` runs. `session.end` with an exit reason (`prompt_input_exit`, `logout`, `other`) closes the split pane after removing converted pictures; `clear` and `resume` leave them.
- Explorer pane `ide-explorer` (`hooks/explorer-panel/`): sections `Files` (tree) and `Preview` (or the Edit section); `files` and `unity` modes, switched by the panel tabs `Files` and `Unity` (pill Tabs `tab:files` / `tab:unity`), on the title row 2 cells apart, with dim "not a Unity project" after the actions (Unity: `.meta` GUID references). Actions, on the title row after the tabs: `refresh`, `edit`, `new`, `mark`, `copy path`, `delete`. The interactive line holds one of, by precedence: the conflict bar, the unsaved-changes bar, the delete bar, the `new` name field. Pure helpers in `tree.ts`, `unity.ts`, `editor.ts` (buffer, ops, keymaps), `edit.ts` (transfer protocol, draft paths).
  - Splitter `split:tree` between Files and Preview/Edit (default 0.35, at least 12 columns a side), fraction in `explorer.split.tree`; `view.treeEnd` (wheel routing, editor width) follows it. A release saves `$.store` `layout:explorer`; `session.start` loads it when the session has none.
  - Tree: labels are cut with `…` to the Files width (`fitLabel`, `tree.ts`), so a narrow Files never wraps a row. The label is the name only, followed by a change mark: `+` added (untracked or staged new, or inside a dir untracked as a whole), `*` edited, and `*` on every dir above a change, deleted files included (`changeMarks`, `markOf` in `tree.ts`, from `git status --untracked-files=normal`, paths from the repo toplevel; kept in `footers` with the branch; none outside a repo). The row client draws it from its `change` prop (`colors.change`: success for `+`, warning for `*`); vscode and mobile a Text after the name. Terminal and desktop draw a row client: a click on a dir's arrow opens or closes it (`toggle`: the cursor moves there, the selection stays); a click on the name or mark selects only (`press`); a double-click (within 400 ms, not on the arrow) copies the path. Enter on the `row:` cell selects; Enter on the selected dir opens or closes it. The name is underlined while the cursor is off the selection. vscode and mobile: Texts, an `arrow:<path>` Button for a dir, the name as the `row:` Button. While editing, a press on a dir or the edited file only moves the cursor (Enter on a dir still toggles); the selection stays on the edited file.
  - File icons (Settings `fileIcons`: `off`, `nerd`, `basic`; pure helpers in `icons.ts`: `iconOf`, `iconChoice`, `iconsFor`, `isNerdFont`): a glyph and a space between the arrow and the name, in its theme role's color (muted for an ignored row), the label 2 cells shorter. `iconOf` matches the whole name first (`package.json`, `Dockerfile`, `.gitignore`), then the extension, else a default; dirs closed / open. `nerd` draws Nerd Fonts glyphs (codepoints checked against Nerd Fonts 3.5.1 `glyphnames.json`: the seti set, Font Awesome folders, `md-unity`), on the terminal only (`iconsFor`: other surfaces draw with their own fonts, so `basic`); `basic` draws `■`/`□` for dirs and a `•` per file in the kind's color. Absent `fileIcons`: `nerd` when Tabby's `terminal.font` or `terminal.fallbackFont` is a Nerd Font build (`parseTabbyFonts`, kept in `themeEnv.fonts`), else `off`. The row client draws it from its `icon` prop; vscode and mobile a Text.
  - `copy path` (key `copy`; the cursor row, else the selected one) and a row's double-click copy the path relative to the repo toplevel (`git rev-parse --show-toplevel`, cached in `toplevels`, cleared by `refresh`; outside a repo, the Explorer root; `relativePath`, `tree.ts`) and toast `Copied: <path>`.
  - Marks (pure helpers in `marks.ts`: `toggleMark`, `rangeOf`, `deleteTargets`, `pruneMarks`): ctrl+click or a click on the mark cell toggles a row (`markToggle`; with no marks, the selection is added first), shift+click marks `selected`..row (`markRange`), `mark` (all surfaces) toggles the cursor row. Ctrl/shift move the cursor, not the selection. A plain click on an unmarked row or Enter clears them; on a marked row they clear after 400 ms (`$.clock.after`), so a double-click copies them all. Marked rows draw like the selected one. Cleared by a mode switch, `refresh`, a delete; closing a dir unmarks rows under it; `Bash` drops marks whose path is gone. While 2+ are marked: `copy paths` (or a double-click on a marked row) copies the relative paths in tree order joined by `\n` (`Copied N paths`); Preview lists them (unless the Edit section is open); `edit` and `new` are not drawn; `delete` asks "Delete N items? (M entries)" (M left out when it equals N) over `explorer.deletingMany`, the marks when the bar opened, and runs one `rm -rf --` over `deleteTargets` (a mark under another marked dir goes with it; `.meta`s in unity mode), then `Deleted N items`. Single and batch delete share `rmArgv`, `runRm`, `afterRemoved`.
  - `edit` (previewed text file): the Edit section replaces Preview. Border Buttons (tinted chips) `save`, `close`, `↑line`, `↓line`, `dup`, `del`; a `●` before the `Edit` title chip while unsaved.
  - Preview engines (pure helpers in `preview.ts`: `ENGINES`, `engineOf`, `parseEngines`, `engineArgv`, `fitCells`, `convertArgv`, `convertedPath`, `pngSize`, `svgSize`, `imageInfo`, `hasSourceView`): `engineOf(name, customEngines)` per extension: `md`/`markdown`/`mdx` → `markdown`; `png`/`jpg`/`jpeg`/`gif`/`webp`/`bmp` → `image`; `svg` → `svg`; else `code`; a custom entry overrides the built-ins. `edit` is drawn for `code` and `markdown` previews of the file itself (not a custom engine's `generated` output).
    - Markdown: our renderer in `hooks/explorer-panel/markdown/` (`parse.ts` → AST (`ast.ts`) via `blocks.ts` / `inlines.ts`; `layout.ts` → rows at a width, contract in `rows.ts`; `view.ts`: pictures, anchors, links), not the built-in `Markdown` element. Covers CommonMark + GFM (tables, task lists, strikethrough, autolinks), alerts (`> [!NOTE]`, top-level quotes), footnotes, `<details>`, YAML/TOML front matter, an HTML subset; the first 1 MiB / 20000 lines (`MAX_CHARS`, `MAX_LINES`). Every row is exactly one terminal row, so Preview scrolls by rendered rows and knows the total. Links: a `Link` element for http(s) outside table rows on terminal, https only remotely (`isLinkable`); any other link is underlined accent text, pressed through a link client on terminal and desktop (`followLink`: `#slug` scrolls to the heading, a relative path inside the root selects it (`jump`), a URL toasts `Link: <url>`, outside the root toasts). A paragraph that is one local image grows into its picture on the terminal (fitted, at most `MD_PICTURE_ROWS` = 12 rows, `expandPictures`), else a `🖼 alt` row.
    - Images: the terminal draws an `Image` (key `preview:image`) from the file itself (a real PNG) or from a PNG converted once per path + mtime to `/dev/shm/ide-panes-preview-<hash>.png` (else `~/.claude/ide-panes/previews/`) by `magick` / `convert` (raster, a gif's first frame) or `rsvg-convert` (svg), detected once per load; none: "install ImageMagick to preview <ext>". Pixels need a kitty-graphics terminal: a `$.ui.blit` of the keyed Image (`probeImage`) answering `alt` sets `imageProbe` and switches to metadata + "terminal can't draw images". Remote surfaces: `.svg` drawn by `Svg` (up to `MAX_SVG_CHARS`), raster images metadata + "image preview needs a kitty-graphics terminal". An info row under the picture: `W×H px · size` (`imageInfo`). Converted files are removed on `ui.close` and `session.end`; `session.start` sweeps day-old ones once per load.
    - Custom engines: userConfig `previewEngines`, JSON of extension to `{ cmd, as }` (`cmd` an argv, `{path}` and `{out}` substituted; `as`: `text`, `code` (highlighted by the file's extension), `markdown` (rendered) or `png` (the command writes `{out}`, drawn as an image)). Runs through `$.process.run` with a 10 s timeout (`CUSTOM_TIMEOUT_MS`); a failure shows metadata and `<cmd>: <first stderr line | timed out>`, cached per file version. `as: text` draws through the code view (so it scrolls); generated output has no `edit` and no source view. Bad entries are left out and toast once per load (`session.start`).
    - The view chip (`preview:view` on Preview's border, `source` / `rendered`; markdown and svg, `hasSourceView`): flips rendered ↔ source (`Code`) through `explorer.previewRaw`, reset with the selection and `previewOffset`.
  - `new`: an `Input` on the interactive line ("new file in <dir>/", `create`, a `cancel` Button); the dir is the selected dir, else the selected file's parent, else the root. `newFilePath` (`tree.ts`) refuses empty, absolute, `..`, trailing `/` and outside-root names; an existing path toasts. It opens the Edit section on an empty buffer (`edit.isNew`, counted as unsaved); the first save writes the file and its dirs.
  - `edit` and `new` only on terminal and desktop (they need a `Client`); vscode (has `Input`, no `Client`) and mobile draw neither.
  - `delete` (all surfaces; drawn when a row is selected and no conflict or unsaved bar is up): a red bar "Delete <name>? (N entries)" (dir, `find` count capped at `1000+`), "+ .meta" in unity mode when it exists, "(open in editor, unsaved)" when the dirty editor is in the target; `delete` / `cancel`. Permanent: `rm -rf --` the target (and `<path>.meta` in unity mode) through `$.process.run`, the explorer's only removal path besides drafts; `deleteTarget` (`tree.ts`) refuses the root, outside-root and odd segments. A failed rm toasts stderr's first line and changes nothing; success closes the editor if it was inside (draft removed), drops the target's, its parent's and its descendants' listings, `footers` and (unity) the GUID index, selects `afterDelete` (next sibling, else previous, else parent) and toasts `Deleted <name>`. Opening the bar closes the `new` field and vice versa.
  - Guards: one dirty check (`guarded`) puts up "Unsaved changes in X: save / discard / cancel" before selecting another file, `close`, a mode switch, `new`, or closing the pane (`ui.close` hook; only `unload` passes). A save whose file changed since load (or a new file's path now taken) asks "overwrite / reload / cancel"; Claude changing the open file (tool hooks) reloads a clean buffer and puts the bar over a dirty one.
  - Draft files: unsaved text is written ~1 s after typing to `~/.claude/ide-panes/drafts/<hash>.txt`; `session.start` bumps `edit.version`, and a draft newer than the file comes back. Save or discard removes it (`rm -f`).
  - Chunked load/save: text crosses between hook and client in 80k-char chunks (`TRANSFER_CHUNK`), each client message acked through props; files up to 4 MiB.
  - Horizontal bar `hb:preview` (`explorer.previewLeft`, reset with `previewOffset`; the Code gutter is digits of the last shown line + 2; total from all lines via `widthCache`) and `hb:edit`: the client owns `left` and sends `{ hview: { left, widest, width }, version }` when one changes (editor columns: a UTF-16 unit or a tab is one cell; the bar counts `widest + 1`, the caret's cell past the end); a drag sets `editing.hview.left` at once and sends the `left` command, which moves the view, not the cursor.
- Git pane `ide-git` (`hooks/git-panel/`), panel tabs:
  - Overview: Branches (under bold `▾ Local (N)` / `▾ Remote (N)` category rows, keys `l:` / `r:` in `git.collapsed`, both open by default; then grouped by `/`, remotes by remote name; on terminal and desktop each row is a branch row client: only the arrow opens or closes a folder or category, a name click selects a branch and does nothing on a folder, a double-click copies the full ref (`origin/main`) or a folder's prefix (`origin/`; a category nothing) and toasts `Copied: <text>` (`copyTextOf`, `copyRef`), Enter on the blank `branch:` / `bdir:` cell selects or toggles; vscode and mobile: Buttons, a category's arrow an accent Text beside its Button) | Commits over Info, two columns at every width. Commits draws one dot per commit (its lane color, from `lanePalette(theme)` in `git-theme.ts`; `○` for merges). On terminal and desktop the dot, `>` marker and short sha are a `Client` column (`hooks/git-panel/dots-client.tsx`, key `dots`; Graph's is `shas`, lanes in their own column before it), each column painting the selected row's `SELECTED`: a left down/up on one row posts `{ press: y }` (`ui.message`: selects that commit, focuses its subject), and resting the pointer ~600 ms on a row's dot or sha (`{ hover: y }`, mapped through `commitWindow`) shows a card of the branches containing the commit (`git branch -a --contains`, `containsCache`) under bold `Local` and `Remote` headings (an empty group's left out), 4 names per group with its own `+N more`, 8 when the other is empty. Info: sha, author, date, parents, refs, the full `local` / `remote` lists of branches containing the commit (HEAD branch `*`, an empty one left out), message, `--stat` (no diff); scrolls on its own, sideways by `hb:info` (`git.infoLeft`).
  - Graph: full-width `Graph` (`git log --topo-order` with `%P`, one row per commit: colored lanes from `layoutGraph`, sha, refs, subject, author, date) over the selected commit's Info, seam `split:graph`. The same hover card on a sha, drawn in Graph's wrapper past the sha, flipped above its row when it would pass the seam.
  - Commit focus key `commit:<sha>`: the subject Button where the sha `Client` is drawn (terminal, desktop), else the sha Button (vscode, mobile; the subject is `subject:<sha>` there). Arrow keys, `autoFocus` and the `ui.focus` hook follow it.
  - Change Log: working tree vs HEAD as Files (always a tree grouped by `/`, as is the diff view's Files) | Diff Preview. Diff Preview (here and in the diff view) scrolls sideways by `hb:details` (`git.detailLeft`): head lines by `sliceCols`, the windowed diff by `sliceDiffCols`, width from `diffGutter` + `widest(diffBody)` (`git.ts`).
  - Diff view: each commit row's `⧉` Button opens Files | Diff Preview for that commit (a merge against its first parent; `filesArgv`, `parseNameStatus`, `fileDiff` in `git.ts`); `back` or any tab closes it.
  - Splitters (Branches | right, Commits / Info, Graph / Info, Files | Diff Preview): `hooks/shared/splitter-client.tsx` (`span: 2`; `split:side` passes `marks` so Commits' `╰` and Info's `╭` corners stay), fractions in `git.split`, pure math in `hooks/shared/split.ts` (`splitAt`, `dragTo`, `layoutOf`). A drag's release saves the whole split to `$.store` `layout:git`; the render reads it once (module `storedLayout`, drawn as `state.split ?? storedLayout`) since a drawing may not write `$.state`.
  - Header line: the title, the tabs, then `back` (diff view only), `fetch`, `pull`, all on one row 2 cells apart; no interactive line (nothing asks), so always 1 row. No `refresh`: tool hooks, fetch and pull clear the caches.
  - `fetch` (`git fetch --all`) and `pull` (`git pull --ff-only`) buttons; nothing else writes to the repo. Pure helpers in `git.ts`.
- Split pane (the only layout; pure helpers in `hooks/shared/layout.ts`: `SPLIT_PANE`, `splitRows`, `splitColumns`, `prefixKeys`, `gitKeyOf`, and `seat`, module state both panels share): one pane, `ide-split` (title `IDE`), opened asking `columns` = 20% of the window (`SPLIT_WIDTH`, at least 24; the window from `/ide-panels`' `presentation.columns`, else the drawing's `viewport.columns`; docked only, and the person's drag of the dock wins). Its body: the Explorer's rows (70%, `SPLIT_TOP`), a one-row seam `split:panels` (a y-axis splitter `Client` on terminal and desktop, a `─` Text elsewhere; at least 8 rows a half, fraction in `explorer.split.panels`, saved with `layout:explorer` on release), then Git's rows. Composition: each panel's hooks match `requestId: [own pane, SPLIT_PANE]`; the Explorer's, registered first and so outermost, set `host` and `seat.gitTop` / `seat.gitRows`, get Git's tree from `next(e)` and stack the two. Git draws at `seat.gitRows` with every key prefixed `git/` (`prefixKeys`, which also walks the element-level `key` and `children` of a tree back from `next`); its ⚙ and sheet are left out, the Explorer's sheet covers both halves. Events: the Explorer's `ui.message`, `ui.focus` and `ui.scroll` hooks pass Git's keys, the wheel from row `seat.gitTop` down, and the scroll keys while Git's half last had the focus (`splitFocus`) on with `next(e)`; Git's strip the prefix (`gitKeyOf`) and count pointer rows from `seat.gitTop`, and `focusGit` adds the prefix back. Closing the split pane asks first while unsaved text is open. Outside a repo (`footers` has no branch for the root) Git's half keeps `NO_REPO_ROWS` (2: title, note), the Explorer takes the rest and the seam is a plain rule (`splitRows(rows, fraction, isRepo)`).
- Repo watch (explorer): a root drawn without a repo is put in `repoLess`, and `watchRepo` asks `git -C <root> rev-parse --show-toplevel` every 2 s (`REPO_POLL_MS`) while the Explorer or split pane is open (a closed pane stops it; the next drawing starts it again). Once a repo answers (`git init`, a clone, by Claude or by hand) it drops that root's footer and `toplevels` and redraws both panels (Git never caches "not a repo"); the drawing that then finds a branch for a `repoLess` root resets `explorer.split.panels` (`resetPanels`, on a timer, since a drawing may not write `$.state`), so Git's half is back at 30% over any dragged size.
- Settings (`hooks/shared/settings.ts`: `DEFAULTS`, `GIT_LIMITS`, `mergeKeys`, `resolveTheme`, `withGitDefaults`, `settingsOf`; the pure sheet and ⚙ in `settings-sheet.tsx`): the ⚙ Button (key `settings`, both panels; pressed on the open sheet = `done`) opens the Settings sheet, focused on the editor keymap in effect (Enter there changes nothing). Controls: Accent from `/color` (default on; a set `/color` also tints section frames); editor keymap preset + key-overrides JSON (over `userConfig`; a bad entry shows an error and keeps the last good text); Explorer default mode (for a root without `explorer.mode:<root>`), File icons (Off / Nerd Font / Basic, the one in effect selected); Git default tab, commits/page (50/100/200/500, default 200); Session (`autoOpen`: open on start, close on exit, default on); Reset layout (immediate, not undone by `cancel`: deletes `layout:explorer` and `layout:git`, both splits → `{}`). Changes apply live to both panels; `done` saves `$.store` `settings`, `cancel` restores the values from opening. While up, the panel's own Buttons do nothing; opening it from the other pane moves the sheet, keeping changes.
- Theme (no choice in Settings): always Claude Code's `/config` theme (`dark`, `light`, `*-daltonized`, `*-ansi`, `auto`; unknown or unreadable is `dark`); the `Theme` type in `hooks/shared/theme.ts`. Pure helpers in `hooks/shared/term-theme.ts`: `CC_PALETTES` (Claude Code 2.1's colors) and `themeFromClaudeCode`, `parseTabbyScheme` (`terminal.colorScheme` of Tabby's config.yaml, `lightColorScheme` while `appearance.colorSchemeMode` is `light`; a profile's own scheme is not seen), `tabbyConfigPaths` (`TABBY_CONFIG_DIRECTORY`, else Tabby's defaults when `TERM_PROGRAM` is `Tabby`). Theme `canvas` is the background painted: the Tabby scheme's background when known (its ANSI colors also serve the `*-ansi` themes and `auto`), else unset (the terminal's own shows), `bg` then a stand-in for the color math. Sources go into the shared `themeEnv` (cleared by each load) through `explorerThemeEnv` / `gitThemeEnv`: the Tabby config looked at again at most every 2 s (`THEME_POLL_MS`, re-read when its mtime changed), the `/config` theme once and then kept by the explorer's `config.set` hook; the explorer's `watchTheme` timer looks again while a panel is up and redraws on a change. A `theme` saved by an older version is dropped by `settingsOf`. Components in `hooks/shared/ui.tsx` (footers draw path, branch and counts as Badges), overlay math in `hooks/shared/overlay.ts`. Section frames use the theme border, or the accent while a `/color` is set. `register.tsx` passes `options` to both panels.
- Caches are module-level in each `index.tsx` (not `$.state`): explorer `listings`, `ignored`, `unityRoots`, GUID `indexes`, `footers` (branch + tree change marks per root), plus `editing` (the editor protocol's side, refilled after a reload), `naming` (the `new` field's dir), `toplevels` (repo toplevel per root, for `copy path`), `widthCache` (Preview's widest line per path + mtime), `pictures` (image preview promises per surface kind + path + mtime), `converted` (every PNG converted this load, removed on `ui.close` and `session.end`), `imageTool` (converters and output dir, detected once), `imageProbe` (the blit probe's answer), `customEngines` / `engineErrors` (parsed `previewEngines`), `customCache` (custom engine runs per surface kind + path + mtime), `mdParsed` (the markdown parse per path, latest mtime only) and `mdCache` (its rows per surface kind + path, one mtime, width, room and probe answer), `mdShown` (the drawn markdown's path, first row, anchors and link runs, for the link message), `repoLess` / `repoWatch` (roots drawn outside a repo, the watch for one appearing) and `deleteFacts` (kind, count and `.meta` per mode + path, for the delete bars); git `repoRoot`, `branchCache`, `statusCache`, `graphCache`, `showCache` (Info per sha), `diffCache` (files + patch per sha, diff view), `changeCache` (diff per path), `containsCache` (local and remote branches per sha, hover card and Info), `hasHead`, `unborn` (the branch HEAD names when none is HEAD; null detached), `storedLayout` (`layout:git`, read once), `diffWidth` (Diff Preview's width per diff string); transient: `hovered` (the card's sha), `commitWindow` (the shas as drawn and the key of the Client drawn for them, `dots` or `shas`; the Client's `y`).
- Footer (Git only; the Explorer has none): `~/path (branch)` left (before the first commit the branch comes from `git symbolic-ref --short HEAD`, `headNameArgv`, as in Git's Branches; the badge reads `detached` only when HEAD is), `+added ~modified -deleted` right (dim when clean; untracked count as added). The Explorer's `footers` (branch and change marks) is cleared with the listings by every hook and `refresh`.
- Cleared by: the Explorer's `refresh` button and each feature's `tool.call` hooks. Explorer: `Write`/`Edit`/`NotebookEdit` drop that file and its parent dir; `Bash` drops all listings (and the GUID index when the command matches `git|mv|rm|cp|unity`). `pictures`, `customCache` and `mdParsed` are keyed by version, so only `dropPictures` clears them (`refresh`, the blit probe's `alt`, `ui.close`, `session.end`); `Write`/`Edit`/`NotebookEdit`, `Bash` and a delete clear `mdCache` alone (an embedded image may have changed); `refresh` also re-detects converters (`imageTool`); each load clears `customCache` (a new `previewEngines` may change what a path previews as). Git: `Bash` clears all and re-reads the branch; `Write`/`Edit`/`NotebookEdit` drop the `git status` cache, `showCache` and `changeCache`; `diffCache` and `containsCache` are cleared only with everything (`Bash`, fetch, pull). The hooks never deny or rewrite a call.
- No hotkeys: every action is a Button pressed by click (or Enter on a focused Button); no Button sets `hotkey`. Keyboard focus navigation (arrow keys, Enter on row cells) and the editor keymap stay.
- Editor keymap: JetBrains by default (ctrl+d duplicate, ctrl+y delete line, ctrl+shift+up/down move lines, ctrl+w extend selection, meta+j next occurrence, ctrl+s save, ctrl+z/ctrl+shift+z); the `vscode` preset swaps in its own. `userConfig` options (`plugin.json`, passed by `register.tsx` to the explorer): `editorKeymap` (`jetbrains` | `vscode`) and `editorKeys` (JSON of action to chord or chords, merged over the preset; bad entries toast once per load); `previewEngines` (custom Preview engines, above).
- Root: both panels take it from `$.session.root()` (stable when the shell `cd`s), not `session.cwd`.
- `$.state` atoms under `ide-panes`: `explorer` (`root`, `mode`, `expanded`, `selected`, `cursor`, `offset`, `previewOffset`, `previewLeft`, `previewRaw` (Preview shows source), `deleting` (the delete bar's target), `deletingMany` (the batch bar's targets), `marked` (the marks), `split` (`tree`, `panels`), `edit` (`path`, `baseMtime`, `isNew`, `hasDraft`, `version`, `conflict`, `confirm`, `pending`)) and `git` (`ref`, `selected`, `offset`, `limit` (absent = the page size; `more` adds a page), `branchOffset`, `detailOffset`, `infoOffset`, `infoLeft`, `detailLeft`, `collapsed`, `tab` (`overview`/`graph`/`changelog`; an old `changes` reads as `changelog`), `change`, `changeOffset`, `changeCollapsed`, `diff`, `diffFile`, `diffFileOffset`, `split` (`side`, `info`, `files`, `graph`); an absent `tab` falls back to Settings), `settings` (`SettingsState`: `accentFromSession`, `keymap`, `keys`, `explorerMode`, `fileIcons`, `gitTab`, `gitLimit`, `autoOpen`), `settingsUi` (`open` (`ide-explorer`, `ide-git` or `ide-split`), `before`, `keys`, `keysError`; session only, never stored) and `sessionColor` (the `/color` name, `''` the default). `$.store` keys: `explorer.mode:<root>` (the saved mode), `layout:explorer` (`{ tree, panels }`) and `layout:git` (`{ side, info, files, graph }`), global section sizes; `settings` (global, the saved Settings); `window:columns` (global, the window width `/ide-panels` last saw).
- The explorer owns the plugin's only `session.start` hook and registers `/ide-panels`; both it and the explorer's `classic.SessionStart` hook seed state through `seedSession`.
- Across sessions of one process: `/clear`, a resume or a fork goes on under a new session id with `$.state` empty and no `session.start`. `session.end` stashes `explorer`, `git`, `settings` and `sessionColor` in the module `stash`; `classic.SessionStart` (any `source` but `startup` and `compact`) restores it, else seeds from `$.store`. Nothing about the conversation resets the IDE. A reload in between drops the stash (the store's presets still apply). Panes stay open and `/ide-panels` stays registered across `/clear`.
- The plugin sets no status line entry.

## Validator constraints

- `hooks.json` `modules` takes one entry; a second is refused.
- One unmatched `session.start` hook per plugin; use a `{ tool }` matcher for each extra `tool.call` hook (one hook per tool per feature; the same `{ tool: 'Bash' }` in two features is accepted).
- `$` is followed only into functions declared in the same file, never across an import: keep `$`-using code in each feature's `index.tsx`, pure helpers in `.ts` files.
- Feature `register`s must be imported by name; no namespace import receiving `on`.
- Every `$.state` key must be declared in `types/index.d.ts`.
- A function handed `$` needs a name unique across the bundled module (both features), and a hook that takes `next` must not declare another `next` in its body.
- Tests: press a Button by key; Buttons carry no `hotkey` (asserted in each panel's tests).
